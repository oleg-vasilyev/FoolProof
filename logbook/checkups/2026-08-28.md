## Findings register

### Medium

1. **Backup reality vs backup design** (known, still open). One snapshot, 2026-08-13,
   hand-made; the monthly path fires first on 2026-09-01; restore-to-service never
   rehearsed. Worst assumption: two weeks of games lost.
2. **The phase-log gate can only ever fire when run by hand.** `phaseLogsOffTheMap`
   checks logs in `git diff HEAD` plus untracked, but the only *automatic* runs of
   `docs:check` — the pre-push hook and CI — happen after the log is committed and
   therefore exempt. That is how `6232fe5` carried four wrong citations that `1d40a75`
   had to fix. The permanent exemption of committed logs is *right*: citations are
   historical records, and re-litigating them against a redrawn flow would force edits
   to history. The *window* is wrong — it never overlaps a gate. Checking logs touched
   by commits not yet on `origin/main` would keep old logs exempt while letting the
   pre-push hook see the new one.
3. **`MEMORY.md:8` teaches the opposite of the owner's 26 August correction.** The
   index line said "открывать finish-phase сразу"; the file it links says the skill
   opens at stage 3, and names the owner catching that on 26 August. The index is what
   every session loads for free.
4. **`finish-phase`'s `description:` fires two stages early** — "Load it when ANY list
   of changes to this repository is accepted", while the skill's own header says
   "Stage 3". The `CLAUDE.md` routing row leans the same wrong way.
5. **`FEATURES` at `eslint.config.js:499` is hardcoded and nothing holds it.** A new
   folder under `src/features/` left off the list gets **no lint fence, silently** —
   the exact never-fires class this project has shipped twice. Held today only by
