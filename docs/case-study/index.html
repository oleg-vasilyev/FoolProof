The harness that learned to check itself

FoolProof is a small Telegram bot that keeps score at Durak; one person built it with Claude Code in six and a half weeks. The bot is the least interesting part: around it grew a harness of rules, checks, skills and agents that decide how the next line of code gets written, and it changed more often than the code it governs. This is its story: what broke, what replaced it, and what it looks like today.

Five findings from the history

This section is for a reader who has never heard of the project and builds software with an AI agent, or wants to. Each finding is a rule that six weeks of history taught, proven by one episode told in plain words; the era below it holds the details.

  1. 01

    An instruction can be skimmed; a check cannot.

    The agent reads its working rules for this project from one file before every session, and still skips them, not out of malice but the way a person skims. One rule asked the write-up of every finished piece of work to record how long the work took; in one week thirteen of sixteen left it out, with the instruction sitting in the file the whole time 08aac82. A check that refuses the write-up cannot be skimmed. So that rule became one, and so did everything else that can be verified mechanically; once the machine holds a rule, its sentence is deleted, and the trigger for the move is a count of misses, never a feeling. By the last commit the checks, rules and instructions that decide how the next line gets written came to 11,332 lines, against 15,829 for the bot itself; the last chart on this page draws the two 09676f7.

    → era 1

  2. 02

    A false pass costs more than no check.

    With no check, a person stays watchful; with a green one, they stop looking, which is why a pass for the wrong reason costs more than an absence. Three times this project had one that verified nothing. A rule meant to keep one part of the code from importing another was switched on, showed green, and was found to match nothing four times in a single day. Another passed only because the files on that machine happened to end their lines the Unix way. Three checks over the project's documents stayed green while the text they guarded was broken on purpose. The habit that came out of it: a new check is trusted only after somebody breaks what it guards, watches it go red, and then searches the code by hand for the shapes of the same mistake it cannot see. When that step became mandatory, fourteen deliberate breaks were made in one stretch of work, and four of them fell outside the check's reach; only the ten that turned it red proved anything, so even the proof of a check has to be checked 5d48dac.

    → era 2

  3. 03

    The best reviewer arrives knowing nothing.

    The model that wrote a thing still holds the reasoning that made it look right, so asking it to review its own work is asking it to read with the answer in hand. A person has the same blindness; here the fix is cheap: start a fresh model with an empty context and a one-line job. So in this project each change is reviewed by a second model that did not write it, a picture the bot draws is described by one that was not told what it is for, every sentence the bot can say is checked with real names and numbers filled in, and a plan is criticised before any code exists. The proof is this very page. A model given it and the project's git history, and nothing else, found 17 of its 263 claims that the commits did not support, and every one of them had read perfectly to the author 5bf13e4.

    → era 5

  4. 04

    Habits built for people fail an AI developer.

    Every tool in a software project is shaped for a person at a terminal: output scrolls past, a result is a line you glance at, a command is something you remember. An AI developer does none of that the same way. It sees only the tail of a long output, forgets what scrolled off, and reads a pass or a fail by searching for it. For six weeks nobody here noticed the mismatch, until a count over one month of the agent's session transcripts found 1,463 test runs it had typed by hand, fishing each answer out of the scroll with a text search af08fc5. Once the tooling was rebuilt for its real user, the scripts went from twenty-three to eight, and every check began to write its verdict, its reasons and the one command that re-runs it into a file the agent opens d49d590. The person at the keyboard was put second on purpose, and lost nothing by it.

    → era 7

  5. 05

    The tooling improves itself in three loops.

    The first loop closes after every task. Each piece of work ends with a retrospective that cannot be skipped: it counts what it cost, rework, a check run twice, a decision guessed, and turns each lesson into a rule somewhere durable, a lint rule, a script that fires on an edit, a line in a written procedure ec3d818. It also leaves one log in a logbook, saying what was asked, what ran, what was rebuilt and which check found each defect db81a3a.

    The second loop closes once a week. A checkup, run by a separate model told to believe nothing on say-so, fix nothing, and cite a command for every verdict, reads that logbook across the week and the running system itself, so a pattern no single task could see shows up as a count: a rule broken in six tasks out of ten, a deploy failing for days 4e56b66. Its reports keep a table of measurements, so the next checkup can ask whether a number moved.

    The third loop measures everything at once. A benchmark gives a model the same frozen task in a copy of the repository, hides the test that judges it, and scores the result with the copy's own checks, so whether the whole set of rules got better is measured rather than argued about; the same run at the same settings every week is what makes the rows comparable d011e68. The loop also has to correct itself, and did: the retrospective once fired after every task regardless and was made conditional, only when there is something to count, because a ritual that always runs and usually reports nothing teaches the reader to skip the line where a real finding would sit fff3c5f.

    → era 7

Forty-six days, one strip

Each commit is one bar, coloured by its era, and a diamond above one marks a release tag. Commits fall on thirty-one of those days. The seven eras are this page’s division, not the repository’s: the lines between them fall where the subject of the work changed. Hover or tap a bar to read the commit; click an era name to jump to its section.

Terms

What “the harness” means here

Everything in the repository that is not the product counts as the harness.

Nine words in the project’s sense

  • CLAUDE.md

    The rules loaded before every session: style, layering, testing, gates.

  • Skills

    Procedures loaded for one kind of job: writing a spec (the test file of one module), adding a feature, finishing a phase.

  • Agents

    Separate model instances with a brief and a contract: a reviewer, a designer, and cold readers, who are deliberately not told what they are looking at.

  • Hooks

    Scripts that fire on an edit or at the end of a turn, a turn being one reply from the model.

  • Lint rules and gates

    What a machine refuses, and what must be green before a commit or a tag.

  • Documents

    The design document, the debt list, the flow drawing, the logbook, and the check that holds all of them against the code.

Three more words recur in the project’s sense. The owner is the single person who sets the tasks and makes the decisions, and the other side of the conversation is the model. A phase is any bounded list of changes, feature or not, that ends at a commit or a tag.

The question the history keeps asking is where a rule lives: in the text the model reads, or in the toolchain, meaning the lint, the hooks and the checks a machine runs. The first answer was given on 29 July and never changed: prose is for judgement, anything else belongs in the toolchain e88417a. The rest of the page is the story of that sentence being tested.

Era 1 of 728–29 JulyCommits 1–30

The rulebook came first

The repository begins with no code at all: two Markdown files, CLAUDE.md and PLAN.md, a .gitignore, and nothing else 44f6f66. The two files already forbade the things the project would spend the next month learning how to enforce, and not one of those rules had a check. The first of them reached the machine by the end of the second day: three paragraphs became ESLint rules, the code got layers that may not import each other, and a tool was grading the tests. Most of the rest took the month.

Tests, and a grader for them312 tests

On 29 July the code got 312 tests in fourteen files and a coverage gate at 70%. The same day brought Stryker, a mutation-testing tool: each small break it plants on purpose is a mutant, and the score is how many of them the tests noticed 9276ad7.

Stryker's opening run gave 88.4%, the project's first mutation score, and the commit reporting it ended at 91.9% fda82cb. Soon after, the threshold for failing rose from 60 to 85, so the gate catches a regression instead of hanging there for show 94b0587. By the end of the era the tests were noticing 94.78% of the mutants 508de4e.

The investment paid back at once: Stryker exposed tests that passed for the wrong reason, one of them checking only that the stub standing in for a dependency had been called. It is the one tool from the first days that every later era kept.

The rules leave the prose3 lint rules

Commit 26, "make the checkable conventions checkable", set the shape of the harness: three rules, no comments, named numbers, blank lines after imports, written straight into the lint config e88417a. The ban on comments is the one a stranger stops at, and the rulebook gives its reason: naming carries the intent, a number that would need a note becomes a constant instead, and a function whose sections need explaining is asking to be split. The code was divided into four layers (shared code, game logic, rendering, Telegram handlers), and each became a zone of banned imports, proved with a deliberate break. A hook on every edit began linting each file as it was written.

The same commit brought two skills and one agent, the project’s first: finish-phase, where the gates moved out of CLAUDE.md; add-repository-method, for new queries; and phase-reviewer, which reads a whole diff and is told not to fix anything.

The rule about where a fact lives appeared when four subjects turned up in both PLAN.md and CLAUDE.md 0afd7b2. The test is one question: would this still be true if the bot were rewritten in Python? If yes, it goes to PLAN.md; if no, to CLAUDE.md.

The tree held 418 tests by the end of 29 July, and what the project knew about writing them had outgrown the rulebook: that part moved out into a third skill, write-a-spec 66ff3bd. CLAUDE.md had nearly doubled in two days, and the cut that followed obeyed a single principle: the file loads before every session, so it may carry only what is true of any line of code. That restraint did not last.

Era 2 of 730 July – 2 AugustCommits 31–66

A green rule can be dead

The first era made the rules checkable; this one learned that a rule can be enabled and silent for days without anyone finding out it is broken. It also gave the project a fake Telegram to play whole evenings against, a debt list where an entry names a trigger rather than a wish, and the documents gate that would grow to thirty families of checks.

A rule found dead, four times in one day13 deliberate breaks

The era starts by turning the source tree inside out: instead of layers at the top (game, render, bot), each feature became a folder with those same three inside it. The rule was stated as a test, “a feature is a folder you can delete”, and verified by deleting one 476f239. Every import came to be written from the root through a hash-sign alias, so a reach into another feature shows in the line itself, which a relative path never does.

The lint rule that fences features off from each other was written, switched on and green, and did not work 476f239. On 30 July four commits found it dead in turn, with one in between that noticed nothing. The first two versions did nothing: a path glob never matched a relative import, then two config blocks silently replaced each other. The third failed because the pattern library read the hash-sign aliases as comments, and proving each direction of the repaired bans took thirteen deliberate breaks 40d8179.

The last two of those four commits found dead exemptions as well, the lines that let a single file out of a rule by name: the logger had moved, and the one written for it still pointed at the path it had left 4d6b389. A Stryker exclusion had gone stale the same way, and the mutation score fell f749a9c. The habit outlived the era: a new zone is finished only when somebody has broken its subject on purpose and watched the lint go red.

“A rule that fires and a rule that is dead look identical from the outside.” f749a9c · 30 July
A fake Telegram7 known faults

By 31 July the product could retry a call, restart itself and report on its own state. Then came e2e: a fake Bot API server, and scenarios that play a whole evening against the bot, tap by tap 3ab3c9c. A single file covers one such evening and holds several cases. The fake was given three rules: record what arrives, decide nothing of its own, and refuse anything the real Telegram rejects.

e2e worked but was not yet a gate; its seven known faults went into a new file, TECH-DEBT.md, under one rule: an entry names a trigger, not a wish, meaning the event after which the debt has to be paid 0505b9b.

Seventy minutes later e2e earned its keep. A new screen with buttons came under one narrow rule: a feature with an inline keyboard gets scenarios. Those scenarios caught two wrong assumptions the model had made, and the commit message records them aea4238. e2e turned into a gate in era 3.

The cost of a gate63 seconds

The same button screen taught the project what a gate costs: an hour and most of a model budget went on eight Stryker runs where two would have done. A budget here is the text the model can read and write in one session. The answer was a mode that mutates only the changed files: 63 seconds instead of four and a half minutes 66564c9.

Two rules came with that cheaper mode and stayed. A gate is never re-run just to read its output a second time. Every phase spends one round on the survivors, the mutants that slipped past the suite, killing each with the test that was missing.

The rulebook overflows585 lines

CLAUDE.md had been the default place to append every lesson and reached 585 lines; it was cut to 354 by moving rather than deleting: the e2e rules went to their own README and the layering procedure to a new add-a-feature skill 4a3d0a9.

Then came the commit "make the documents check themselves" 29fe4d5. The documents had been de-duplicated twice already, and its message blamed the rule on where a fact lives: nobody checked it. So it added the documents gate, spelled docs:check then and check-docs today. At first it covered links, the tree the README draws against the real folders, the script table against package.json, and a 380-line budget on CLAUDE.md; its first run found two undocumented scripts. By the end of the story it holds more than thirty groups of checks, each about one subject, which this page calls a family.

A lesson left in the chat is gone5 questions

The era ends with the retrospective, and the first attempt at one failed. The step was hung on compaction, the point where a conversation outgrows the model's memory and is squeezed into a summary, and a hook was to put five questions just before it: about rework, repeated commands, subagents, sequencing and re-reading. That hook had no way to return a line of text, so nothing it asked reached anybody, and it was deleted the same day ec3d818. Compaction was the worst moment available in any case.

The retrospective became a gate, the fifth and at that time the last, and a skill of its own. Its first result was a narrower delegation rule: hand work to an agent only when the model’s own context is running out ecc6395. The owner overruled that in era 4.

Era 3 of 75–7 AugustCommits 67–121

Checks that read the code

Over three days the harness began reading the source as well as the documents: the scenarios became a gate, every name of a game state moved into one table, and docs:check learned to test a claim in prose against the code that runs. Along the way a lint rule caught the model that had written it, and two gates turned out to have been green by accident for as long as they had existed.

e2e becomes a gate6 gates

e2e still carried seven recorded problems; six of them were closed in one commit.

Before the scenarios could be a gate they had to be taught to end the way a real evening ends. A running game lives in a single message with buttons, called the card, and eight of the sixteen scenarios stopped while it was still open. e2e now fails a scenario that stops there.

As a gate, e2e plays only the scenarios the diff can reach: a change inside one feature usually means two or three files, and its e2e scenarios run in about fifteen seconds 52c0f73. From that commit the work ends with six gates in a fixed order: lint and types, coverage, mutation, e2e, the review, the retrospective; the third and fourth run over the diff alone, meaning the files the phase changed.

Writing an e2e scenario got a skill of its own, for a reason about what makes a skill open: the model loads one when its description matches what it is doing right now. CLAUDE.md said to read the README before touching the scenario folder, and the README stayed shut while a phase edited a file there: to the model the edit was adding a case, and the folder never entered its mind. The skill now opens on any edit to a scenario a0fcb61. The same lesson returns in era 4 and costs more.

The rule that caught its own author5 more sites

Every string the code used to name a game phase, a button press, an outcome or a refusal moved into one table per feature, and a lint rule banned spelling any of them out anywhere else. 3c0b283

The test files were exempt at first. Three commits later the review caught a spec comparing a state against a bare string, written after the ban came into force and by the very model that had drafted it. The exemption ended there, and once the specs came under the rule too, five more sites turned up in the production code. a89a991

A release review then found a function still returning a game state as a string: the rule knew three shapes, and a returned value was a fourth. dc2602c That added one more step to the ritual from era 2: after a rule has been shown to fire, search the whole tree once for the shapes it cannot reach, because lint catches only the syntax somebody thought of.

docs:check learns to read the code3 palettes

The documents gate grew from links and budgets into a truth-checker, one family at a time, each added after something had been found wrong.

One family checks the database schema, the SQL in PLAN.md against what the bot actually runs. It arrived after a database created from the document alone failed on its first command, refusing a record with a required field missing. a24c0d4

Another redraws the posters and compares them with the committed ones, so one changed colour code turns the gate red. It arrived after the pictures were held against their design mockup and three palettes, two font families and two widths were found in play, with no document saying which was right. 73b4f3a

Two gates found lying5 of 17 scenarios

Two gates had been green by luck. The first was the e2e quiet window, the 600 ms a scenario waits before it reads the screen. The usual poster render had meanwhile grown from 460 to 540 ms, which left 60 ms of that wait, and five of seventeen scenarios went red on a bot that was working. Those failures looked like flakiness, but they were measured rather than waved away, and the window was doubled. 2e7c639

The second was the documents gate, which could not read a checkout whose files ended in CRLF. The author's copy happened to hold Unix endings, so the gate was green; on a fresh clone it would have gone red on a tree where nothing was wrong. 6ddd56e The release of 1.7.0 names both. 4422ddb

Era 4 of 711–14 AugustCommits 122–184

The bot leaves the laptop

Sixty-three commits came in four days, and three things in them stand out. The first is a gate no machine can answer: a poster is a picture, and a test cannot look at one. The second is the bot's move to a server that waits for nobody. The third is a phase that ran six gates and released without the seventh.

The gate a machine cannot answer9 evenings

A gallery was built: nine awkward evenings, each drawn twice, as the chronology and as the awards poster, seventeen pictures in all, because nobody earns anything in a one-game evening, so it has no second poster. Looking at them became the fifth gate, and the gates became seven ce3c70c. The viewer was the model that had drawn them, briefed in the phase skill to make specific claims about each picture, never a verdict; its first run caught two holes in the rules that decide which player earns an award, THE COMEBACK for example, and a line of text running off the edge of an award's card. Two days later the check moved to after the review, because a picture passed at the fifth gate could be stale one step later; whose eyes it needs is settled only in era 5 743adaa.

“‘Looked, fine’ is the green light with nothing behind it.” ce3c70c · 11 August
Delegation becomes the rule3 conditions

In era 2 the rule had been to delegate only when the model's own context was running short. The owner overruled it: an independent piece of work goes to an agent straight away, provided it touches no file the model has open, the brief fits in one message, and nothing but the result needs to come back. The review is now always the phase-reviewer agent's job, never a second reading of the diff by whoever wrote it. The retrospective counts which pieces were delegated and which were kept, because a new default that quietly goes unused leaves no trace at all 0352b2b.

A later commit set the limit of the review: the agent reads the diff and executes nothing, so a green verdict on a shell script, a systemd unit or a workflow is half a gate, because all three are files only a run can check. 6a4c252

One battery becomes three3 batteries

The server pulls the newest tag every five minutes and nothing pushes to it, so a broken release is running before anyone can react; the single check therefore split into three, by what is at stake at each moment cfd02a1. Before a push CI runs lint, types and the documents: a push changes the site and the text, not the bot. At the end of a phase the four machine gates go as one command. Before a tag comes the full battery: coverage, every mutant, every scenario f58e793.

The battery sits in a git hook on the developer's machine and runs before a tag leaves for GitHub, because the server picks it up within five minutes of landing: by the time CI turns red, the broken bot is already running. 3b22b7c

The flow drawing gets hooks8 stages

The whole development loop was drawn as a sequence diagram in DEVELOPMENT-FLOW.md. edc1148 Today it has eight stages: framing the task and the mockup, code and tests, the machine gates, a review by an agent that did not write the diff, reading the sentences and syncing the pictures, the retrospective, the release, and the checkup.

It is the owner's drawing: it may not be changed quietly, and permission may not be asked for either, so the rule is to move the step and report it in the closing message, with counts. Three things watch it: a hook that states the obligation on every edit, a commit-message check that refuses a moved step without a reason, and docs:check, which fails when the drawing names a skill or script that does not exist. 5eb6933 912be9b

Nothing audits the auditors13 findings

The deep-checkup agent was written to run weekly, believe nothing on say-so, fix nothing, and return a report in which every verdict cites a command and its output. 4e56b66 Its first run took 33 minutes and produced thirteen findings, the highest being that the database had no copy anywhere and no restore had been rehearsed; a verified daily backup followed, and the other twelve closed in one commit. 0ba2815

The retrospective that was skipped27 rows

There were seven gates, the retrospective stood last, and one phase went out without it. The first explanation blamed the release for feeling like the end 6799bd8; the next commit, after the owner corrected it, found the real reason: the work had followed a findings register of its own, 27 rows from an audit, none of them a gate, and once the rows were done the phase looked finished fdab9be.

The fix was to the trigger. All twelve descriptions were checked against the table in CLAUDE.md that routes a job to its skill, and against the drawn stages. The four that disagreed were rewritten to name the task they are needed on, because the description is what decides whether its skill is opened at all. docs:check began failing when a skill or agent is named nowhere in CLAUDE.md f6f617b. Era 3 had met the lesson on the scenarios; here it cost a skipped gate.

Era 5 of 719–25 AugustCommits 185–244

Cold readers and the budget squeeze

A released poster told the players “one dot per evening — 3 more evenings” and never said what would arrive. The owner read it without knowing what stood behind it and asked what it meant, and that question is where every stranger-reader in this project comes from. Then the harness was turned on itself: its own checks were tested and its size was capped.

The author cannot read their own drawing9 gates

Those dots stood in for a chart the poster draws only once enough evenings have been played; until then a hint takes its place. So an agent, poster-reader, is handed the pictures and the list of lines on them and nothing more, and reads them with no idea what any of it is for. Its first run reported seventeen findings on twenty-nine drawings, and the gallery became the one gate the author of a picture may not perform alone. da50714

The same failure existed in words. Reading one real evening before a release became a gate, owed whenever a phase changes what a poster says; until then nothing had asked what an evening's chronology actually told the players. 93c1456

Two real evenings yielded eight defects in ten minutes, so the sentences got an agent of their own: copy-reader takes every line the bot can say, in both languages and with real values in place, and asks whether a person would put it that way d45f2f0. With this check and the evening reading in place, the phase ritual stood at nine gates. Some sixty points came out of the first passes, most of them acted on, and the next day a second commit moved copy-reader earlier, to the moment a table of lines is written fff3c5f.

The plan-reviewer agent works at the start of a phase, when the plan exists and the code does not; it gets the owner's words and the agreed signatures, may come back with nothing, and owes only an account of what it checked. Calibrated on a plan with three planted faults, it found all three and a fourth. e64c8cd

A gate that silently does not apply80% bar

The product got its third poster, one player's whole career, and it shipped in two releases with no gallery case, because no rule said a new picture owed one: a gate that does not apply looks exactly like one with nothing to report. 2b1353b da16c8d

The checkers got checked themselves: every document rule was broken on purpose, and nine went red while three stayed green 3d92c6b. The checks were then rewritten as pure functions with specs and given a Stryker run of their own, whose first score was 47.17%, the share of the documents gate’s own mutants its tests caught. The bar was set at 80% and kept separate from the bot’s, because a single average over both sets, the bot’s four times as large, would have read in the nineties and buried a gate scoring under half 471cac4.

Budgets everywhere16% of changed lines

CLAUDE.md had carried a line budget since era 2; now every skill got one, and so did TECH-DEBT.md. finish-phase had grown to 722 lines and was cut to 459, with five pages moved beside it, and the limits were lowered in the same commit, so that splitting a file cannot switch the counter off. ab68474

A fresh model reviewed the work from outside and found that 16% of the lines changed over five days had gone into the process rather than the product. It also counted eight releases in four days, each one restarting the bot and paying again for a whole mutation run and every e2e case. Three things became conditional: a tag is cut only when a player or the operator gets something new, a writing job goes to an agent once it reaches ten files, and a retrospective waits until there is something to count. fff3c5f

The era's last commit tested an idea: that a skill should name the outcome it wants instead of listing the steps. It did not hold. One skill rewritten to almost half its length lost six concrete instructions: the war stories that had prompted them stayed on the page, while the repair each story taught was squeezed out. With that danger named in the brief, the next skill came through the same treatment with every instruction intact, and skill-auditor now takes an inventory of a skill, rule by rule, before anyone shortens it. 784b26c

Every agent got a contract: what its brief must carry and what it must return. The return opens with one verdict line holding two numbers, the share covered and the count found, and the findings follow. Without those numbers, an agent that covered half of what it was asked sends back a report that looks exactly like a full one, and whoever acts on it never checks. ba4603f

A hook on the end of a turn came from one phase that stopped on a message listing what was left, ended with “Continuing”, and did nothing; no gate could notice, because there was no diff. The hook reads the last sentence of a reply and refuses a turn that ends by announcing work instead of doing it. 2239ef0

Era 6 of 726 August – 2 SeptemberCommits 245–274

The harness keeps its own records

This week added almost nothing new. Instead it found what the existing checks could not see: the linter had skipped a folder and every dynamic import, and the table that sent the model to a skill had drifted away from the skills themselves. And the harness started keeping a logbook of every phase it ran.
