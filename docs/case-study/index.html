The harness that learned to check itself

FoolProof is a small Telegram bot that keeps score at Durak. One person, working with Claude Code, built it in five weeks, and the bot is the least interesting part. Around it grew a set of rules, checks, skills and agents that decide how the next line of code gets written, and that set was rewritten more often than the bot was. This is the story of that set: what broke, what replaced it, and what it looks like today.

Every claim comes from the commit history. Where a motive is inferred rather than stated in a commit, the text says so. Every number is read from git, and every hash links to its commit.

Terms

What "the harness" means here

The harness is everything in the repository that is not the product.

  • CLAUDE.md

    The rules loaded before every session. Style, layering, testing, gates.

  • Skills

    Procedures loaded for one kind of job: writing a spec, adding a feature, finishing a phase.

  • Agents

    Separate model instances with a brief and a contract: a reviewer, a designer, and cold readers, who are handed the artefact and nothing else.

  • Hooks

    Scripts that fire on an edit or at the end of a turn.

  • Lint rules and gates

    What a machine refuses, and what must be green before a commit or a tag.

  • Documents

    PLAN.md, TECH-DEBT.md, the flow drawing, the logbook, and the check that holds all of them against the code.

Two words recur in the project's own sense. A phase is any bounded list of changes, feature or not, that ends at a commit or a tag. A gate is one of the checks a phase must pass on the way. The question the history keeps asking is which part of the harness a rule belongs in, and the first answer, given on 29 July, never changed: "Prose is for judgement; anything else belongs in the toolchain." e88417a

Era 1 of 628–29 Julycommits 1–30

Two Markdown files

The repository begins with no code. The first commit is a spec (PLAN.md, 286 lines) and a rulebook (CLAUDE.md, 173 lines) adapted from a sibling project. 44f6f66 The rulebook already says the things the project would spend a month enforcing: no comments in src/, a named constant for every number, a pure reducer with no I/O, one file allowed to contain SQL, every user-facing string in one copy table. What it did not have was anything that checked them. Closing that gap took the whole five weeks; the first two days set the shape of how it would be done.

The second commit swaps PostgreSQL for SQLite and adds the first hook: a Stop hook that runs lint:fix at the end of every turn. The third adds ESLint with five rules, and its header comment admits the limit: the no-comments rule "has no ESLint equivalent and stays a review convention." That sentence lasted one day.

Tests arrive, and then a grader for the tests

On 29 July the code got 312 specs and a coverage gate at 70%. 9276ad7 The same day it got Stryker, a mutation-testing tool: it breaks the code in small deliberate ways and counts how many of the breaks the tests catch, because "coverage says a line ran; it does not say a test would notice if that line broke." The first run scored 88.4%, and that figure, the mutation score, is the one this story tracks from here. The break threshold went 60 → 85 within four commits, with the stated reason: so that the gate "bites on a regression rather than sitting decoratively below it."

Mutation testing found what coverage could not: tests that passed for the wrong reason. A mocked dependency "only tests what you assert about the call." A SIGTERM test passed only because the SIGINT test above it had left a spy dirty. The entry file had been excluded from coverage as a file no test could import; the commit that rewrote that exclusion admits the reason "was doing double duty as an excuse," 8231393 and two commits later the exclusion was gone.

The rules move out of prose

Commit 26, "make the checkable conventions checkable", is where the shape of the harness was set. e88417a Three inline ESLint rules replaced three paragraphs: no-comments, named-numbers, blank-lines-after-imports. Layering became no-restricted-imports zones, "verified by linting deliberate violations, since a zone rule that never fires proves nothing." A PostToolUse hook, which fires after each edit, started linting every file as it was written. And the first two skills and the first agent appeared: finish-phase (the gates, moved out of CLAUDE.md), add-repository-method, and phase-reviewer, which reads a whole diff and is told "Do not fix anything."

Two more ideas from the same two days survived everything that came after. One is the ownership rule for documents, written when four subjects had been duplicated across PLAN.md and CLAUDE.md: "would this still be true if the bot were rewritten in Python?" If yes it belongs in PLAN.md; if no, in CLAUDE.md; "a fact lives where its reason lives; the other document gets a pointer, never a retelling." 0afd7b2 The other is "units by default, integration by exception": a spec tests one file and mocks everything else, and a test that passes without asserting on the thing it changed is "the bad kind of passing."

By the end of 29 July the testing craft had outgrown the rulebook and became the third skill, write-a-spec. CLAUDE.md, which had grown from 173 lines to a peak of 317, ended the era at 228: "CLAUDE.md is loaded on every turn, so it should hold what is true while writing any line of code." 66ff3bd

Era 2 of 630 July – 2 Augustcommits 31–66

Features you can delete, and rules that prove they fire

Era 1 made the rules checkable. Era 2 found out that a checkable rule can be dead, and that nothing tells you.

It starts by turning the source tree inside out. Instead of layers at the top (game/, render/, bot/), each feature became a folder with those layers inside it, and the rule was stated as a test: "a feature is a folder you can delete." It was verified by deleting one. 476f239 Every import became a # alias, so a violation shows in the line rather than in the folder you happen to be looking at.

A rule found dead, four times in one day

Fencing features off from each other with lint produced the lesson the project would repeat most often. The first two versions of the independence rule did nothing: one glob never matched a relative path, and two flat-config blocks setting the same rule silently replaced each other. In the next commit minimatch read the # aliases as comments, "so #live-game/** matches nothing and the zone passes everything." 40d8179 Moving the logger to a folder left the no-console exemption pointing at a file that no longer existed. Moving the SQLite connection did the same to a Stryker exclusion, and the score dropped by nine unkillable mutants nobody had asked for. f749a9c

Four commits on 30 July, each finding a rule that had never fired, all silent. The response was a habit rather than a fix: "a new zone is not finished until a deliberate violation has been shown to fail the lint." Thirteen deliberate violations were run to prove one commit. Exclusions switched to basenames, which was only safe because unique file names had become a rule the same day.

"a rule that fires and a rule that is dead look identical from the outside." f749a9c · 30 July

A fake Telegram, built and parked

By 31 July the bot could retry, restart itself and answer /status. Then it got an end-to-end rig, which the project calls the e2e harness: a fake Bot API server and scenarios that play a whole evening against it. 3ab3c9c The rules for the fake were "learned by getting them wrong": it records and never decides, and it must refuse everything the real one refuses.

Then it was parked. TECH-DEBT.md was created to hold it, with seven honest faults listed and a rule for the file itself: "an entry names a trigger, not a wish." 0505b9b Seventy minutes later, just past midnight, /merge brought it off the bench under a narrow obligation, "a feature with an inline keyboard gets scenarios", and the scenarios "immediately caught two wrong assumptions of mine about the bot's own behaviour."

The cost of a gate

/merge "took an hour and most of a model budget, and the breakdown was not the feature: eight Stryker invocations where two would have done." The answer was test:mutation:changed, which mutates only the files that differ from main: 63 seconds instead of four and a half minutes. 66564c9 Two rules came with it and stayed: "Never re-run a gate to re-read its output", and one round per phase of killing survivors, the mutants no test caught.

The rulebook overflows

CLAUDE.md had been the default place to append every lesson, and it reached 585 lines. It was cut to 354 "and nothing was deleted": the e2e rules went to e2e/README.md, the layering procedure to a new add-a-feature skill. 4a3d0a9 Twenty-three minutes later the commit "make the documents check themselves" observed that the documents had now been de-duplicated twice, "which means the rule was never the problem," and added scripts/check-docs.ts, the documents gate the rest of this story calls docs:check. 29fe4d5 It checked links, the README tree against the real folders, the script table against package.json, and a 380-line budget on CLAUDE.md. Its first run found two undocumented scripts.

A lesson left in the chat is gone

The era ends with the retrospective. The first attempt was a hook on compaction, the moment a long conversation is squeezed to fit the model's window, and it asked five questions: about rework, repeated commands, subagents, sequencing and re-reading. It was deleted the same day: the event had no channel for returning text, "so the hook failed schema validation on every compaction," and compaction was "the worst moment available" anyway. ec3d818 The retrospective became a gate, the fifth, and a skill. Its first outputs rewrote the delegation policy, from "mechanical work goes to a subagent on a cheaper model" to a measurement (one phase had spent 493k tokens across six agents, and only the review pass had paid for itself) and a narrower rule: delegate only when your own context is scarce. ecc6395

Era 3 of 65–7 Augustcommits 67–121

Scenarios become a gate, states become tables

Three days and five releases, in which the checks stopped reading only the documents and started reading the code as well.

The e2e harness becomes a gate

The parked harness had seven problems. Six were closed in one commit, the seventh recorded as impossible on Windows, and npm run e2e:changed became a gate: it plays only the scenarios the diff can reach, and "a phase inside one feature usually plays two or three files in about fifteen seconds." 52c0f73 From that commit the phase ends with six gates in a fixed order: lint and types, coverage, mutation over the diff, e2e over the diff, the review, the retrospective. First, though, scenarios had to be made to end the way an evening ends: eight of sixteen had "walked off mid-card" with buttons still open, and the harness now fails any that do.

Writing a scenario got its own skill, for a reason about how skills are found. CLAUDE.md had routed "touching e2e/" to the README, and a phase edited a scenario "without opening the README once, because that felt like adding a case, not like touching e2e/." The skill surfaces on "editing a *.e2e.spec.ts" rather than on "touching a folder." a0fcb61 The same lesson returns, larger, in era 4.

The rule that caught its own author

Every state name (phases, taps, outcomes, refusals) was moved into a frozen table per feature, then a lint rule, named-states, banned a string literal in a case clause or a comparison. Installing it "caught five real ones in shared/." 3c0b283 Specs were exempt at first. Three commits later the review found a spec comparing against a bare "untouchable", "added after the rule existed, by the person who wrote the rule," and the rule was extended to specs, where it found five more production sites. A further shape, a literal returned from a typed function, arrived after a release review found phaseOf still returning "READY" well after the phase table existed. The ritual gained a line for this: after proving a new rule fires, "grep the whole tree for that shape once", because "a lint rule catches the syntax somebody thought of." dc2602c

docs:check learns to read the code

The documents gate grew from links and budgets into a truth-checker, one family of checks at a time, each added after something had been found wrong. It parses the schema in PLAN.md and compares it with the CREATE TABLE statements the bot actually runs, after a schema recreated from the document "failed the first /game on the NOT NULL constraint." a24c0d4 It re-renders the committed posters and fails on one changed hex, after a comparison found "three different palettes in play, two font families and two widths — nothing anywhere said which was true, because nothing could." 73b4f3a And it fails a layer root with more than nine files, after two folders were split and, the same day, renamed again because they had been named after processes.

Two gates found lying

The release of 1.7.0 says it plainly: "Two gates were found lying on the way, both by accident and both for as long as they have existed." 4422ddb The e2e quiet window, the pause a scenario waits for before it reads the screen, was 600 ms; when the render grew from 460 to 540 ms the picture began landing after the window had closed, and "five of seventeen scenarios started asserting against pictures that had not arrived. The failure looked exactly like flakiness." The documents gate could not read a Windows checkout with CRLF line endings, so on a fresh clone it would have reported every table undescribed "on a tree where nothing was wrong."

The era also gave the bot Russian, and with it the rule that copy is a parameter, never an import, so no module can pin the bot to one language. fa668dc

Era 4 of 611–14 Augustcommits 122–184

The bot leaves the laptop

Sixty-three commits in four days, ten releases, and the largest change of setting: the bot moved to a server. With it came the first gate no machine can answer and the first audit of the harness itself.

The gate a machine cannot answer

A poster is a picture, and no test reads one. The gallery gate draws nine awkward evenings into seventeen PNGs and asks whoever looks for "specific claims, not a verdict, and 'looked, fine' is the green light with nothing behind it." ce3c70c Its first run caught two award rules with holes and a line of text leaving the card. Two days later the gate was moved to after the review, because "a picture checked at gate five could be stale by gate six." 743adaa

"'looked, fine' is the green light with nothing behind it" ce3c70c · 11 August

Delegation stops being a favour

The rule from era 2, delegate only when your own context is scarce, was overruled by the owner. The review pass became "always the phase-reviewer subagent, and never a re-read," and independent scopes are delegated on sight under three conditions: no file you have open, a brief that fits one message, and only the result matters. 0352b2b The retrospective was told to measure it, because "a new default fails by quietly not being used, not by being used badly." A later commit added the reviewer's limit: it reads the diff and runs nothing, so "a green review of a shell script, a systemd unit or a workflow is half a gate." 6a4c252

Deploy, and three wrong lock files

The server pulls the newest tag every five minutes; nothing pushes to it. cfd02a1 Running the deploy script found two bash bugs. The systemd unit's restart limit is "deliberately the same shape as the supervisor's rule one level down." And a lock file written on Windows failed on Linux twice in this era, and a third time a week later. That produced a gate step (npm ci --dry-run), then the admission that "the local dry run said yes" both times, then the instruction to diff the lock for removed lines and restore rather than regenerate. ab89f77

The single check script split into three by what each moment risks: check:push, check:phase, check:release. CI runs the first on every push. The full battery runs on the developer's machine in a pre-push hook before any tag leaves, because "CI on the tag can only report, never hold." 3b22b7c

The flow gets drawn, and the drawing gets hooks

The whole development loop was drawn as a Mermaid sequence, first beside the retrospective skill, then on the README, then as its own file, DEVELOPMENT-FLOW.md. edc1148 When a step moves, the redraw is reported, never asked for. A PostToolUse hook states the obligation when the file is edited; a commit-msg hook refuses a commit that moves a step without a Flow: paragraph and without touching whatever backs the step; docs:check fails if the drawing names a skill or script that does not exist. 912be9b

Nothing audits the auditors

The deep-checkup agent was written to run weekly, "believe nothing on say-so," fix nothing, and stamp the wall clock. 4e56b66 Its first run took 33 minutes and its highest finding was that no backup existed and no restore had been rehearsed. A verified daily backup followed, then the other twelve findings closed in one commit. 0ba2815

The retrospective that was skipped

One phase "ran six gates and released without the seventh." The first explanation blamed the release feeling like the end, and the next commit corrected it at the owner's word: the phase had worked from a 27-row findings register, "none of them a gate," and the skill was never opened. 6799bd8 The fix was not another rule but a change in where rules are found, the lesson era 3 had met with e2e/. All twelve skill descriptions were checked and four rewritten to say when the skill fires, because "a skill description is not documentation about the skill — it is the trigger that decides whether the skill is opened at all." fdab9be And docs:check began failing when a skill or agent is named nowhere in CLAUDE.md.

Era 5 of 619–25 Augustcommits 185–244

Cold readers and the budget squeeze

The product got its third poster, one player's whole career. The harness got five agents, most of them readers who know nothing, and then a set of limits on how much harness there may be.

The author cannot read their own drawing

The owner read a released hint on a poster cold and asked what it meant. That is the origin of the cold readers. poster-reader is briefed with pictures and the list of lines on them and nothing else, and reads them "cold, with no idea what any of it is for"; "It is the only reader here whose ignorance is the instrument." da50714 The gallery gate became "the one gate you may not perform yourself." Its first real run reported 17 findings across the 29 drawings the gallery had grown to.

The same failure existed in words. Two real evenings run through the awards produced eight defects in ten minutes, so copy-reader reads every copy line in both languages with real values filled in and asks whether a person would say it. d45f2f0 Its first four readings found 62 things, about 50 of which were acted on, and it was then moved earlier: to the moment a table is written, before anything is built on it.

plan-reviewer closed the other end. It gets the owner's words and the frozen signatures, nothing more, and comes with "No quota. You may come back with nothing." Calibrated on a plan with three planted faults, it found all three and a fourth. e64c8cd poster-designer is the one that draws rather than reads: it returns a contact sheet, every edge case on one image beside the neighbouring poster, with an inventory of every mark in a player's words.

"It is the only reader here whose ignorance is the instrument." da50714 · 20 August

A gate that silently does not apply

/personal shipped in two releases with no gallery case, because no rule said a new poster owed one: "A gate that does not apply is indistinguishable from a gate with nothing to report." da16c8d Then a checkup broke every docs:check rule on purpose and three stayed green. Then the tooling itself was put under Stryker, and the document checks scored 47.17% the first time. They were rewritten as pure functions with specs and given their own mutation family with an 80% bar, kept separate because "1400 tooling mutants averaged with 5600 good ones would have read as 93% while a gate sat at 56%." 471cac4

Budgets everywhere

CLAUDE.md had had a line budget since era 2. Now every skill got one, "a skill with no row fails the gate too," and TECH-DEBT.md got one with a rule that every entry ends on a trigger. finish-phase had grown to 722 lines and was cut to 459 with five pages beside it; the budgets were lowered in the same commit "so the split cannot be a way to turn the counter off." ab68474

An audit run by a fresh model with no memory of the work put a number on the churn: 16% of five days' changed lines had gone into the process, and eight tags in four days. fff3c5f Three things became conditional: a tag only when a player or the operator gets something new; delegated writing only above ten files; a retrospective only when there is something to count.

The last commit of the era tested the claim that a skill should state outcomes rather than steps. A cold rewrite of one skill from 166 to 91 lines lost six remedies: "the war stories survived as symptoms while the fixes they bought were compressed away." With that in the brief, another skill was cut with forty remedies of forty kept. A skill-auditor agent now inventories a skill rule by rule before anyone shortens it. 784b26c

Every agent also got a contract, What the brief must carry and What comes back with a Verdict: line, because "a narrowed pass reads exactly like a completed one, because nothing downstream is watching." ba4603f

Era 6 of 626 August – 2 Septembercommits 245–274

The harness keeps records of itself

The final stretch added few parts. It fixed how the existing ones are found, timed and remembered, and it caught the harness's own counts being wrong.

Blind spots in the lint

A round of skill audits found that eslint had never been run on e2e/, and that the import zones read only static import statements while 102 spec files loaded their subject with await import(...). Every ban is now compiled a second time into a syntax rule. fee84a4 The hand-written list of features in the lint config was replaced by reading the folder, because "a folder left off it got no fence at all, silently." Two rules that had been prose and review became lint, one of them as old as the first commit: only one file may open the database, and every screen's Cancel and Confirm row is assembled in one place. 76a0ee0

Where a skill says when it is due

CLAUDE.md had opened with a routing table since era 2. It was deleted: "a fact stated in two places is the copy that rots." Each skill's description now names the stage of the flow it belongs to, and docs:check holds the two against each other. When that gate was wired in "it fired on all twelve — not one description in the repository had ever said when it was due." 01ef471 The description of finish-phase flipped from "Load it when ANY list of changes to this repository is accepted" to "Do NOT load it at stage 1," after the checkup found that wording firing two stages early.

description: "… This is stage 3 and the stages after it, so load it when the code is written and the gates are due — a phase being wrapped up, a release being cut, an external list of changes that has run out, or the user asking whether the code is releasable. Do NOT load it at stage 1: recognising a list of changes as a phase is not the same as opening this skill …"

The routing table CLAUDE.md opened with from 4a3d0a9, and the skill's own front matter after 01ef471 deleted the table.

The flow, corrected five times in a day

Reading the flow drawing as prose found steps under the wrong guard: the fault-only branch held orientation steps every phase needs; a question errand was drawn at stage 4 when it happens before the owner is asked. Seven flow commits landed on 26 August, five of them moving a step to where the work happens, and two of them admitting that "nothing mechanical checks that a step sits where it actually happens." 650cdec

The logbook

The answer to that was a record. logbook/phases/ holds one log per phase, written at the retrospective: what was asked, what kind of work it was, what ran, what was delegated, what was rebuilt, and which gate found each defect. db81a3a Path: and Skipped: cite the flow drawing by its own opening words, and between them must name every stage, so a phase that quietly went round one reads differently from one that did not mention it. The gate reads a log exactly once, in the commit that brings it in. f4b09e7 The one rule that matters: "A number you did not measure is written not measured, never estimated." The first log written under it had two counts wrong: "both were one git log away, and both were wrong in the direction that made the day read better."

logbook/checkups/ keeps every checkup report, never pruned, with a measurements table, so the next visit can ask whether a number moved. The first one is there: 6823 mutants, 121 survived; 178 e2e cases in 109 seconds on a cold clone; 1.7 GB of leftover reports. b8cb5ea

Counts rot

The most repeated lesson of the last era is small. "129 files" was 102, because a grep counted typeof import(...) too. "Four rules with no core equivalent" became "several." A Lines column in TECH-DEBT.md was dropped because half of it was stale and no gate could have said so. "Thirty-six awards" was forty-five in six places, and then the number was removed entirely, with a gate for it considered and rejected: "a check defends a fact something depends on, and nothing depends on this one." 25108af

What kept coming back

Six patterns run through the whole history. Each was stated in a commit, not inferred.

  1. 01

    Prose becomes a machine

    Every rule starts as a sentence in CLAUDE.md. If a machine can check it, it becomes a lint rule, a hook or a docs:check family, and the sentence is deleted. Seven project lint rules and 32 documentation checks are the residue.

  2. 02

    A rule that never fires looks clean

    A rule found dead four times in one day, a gate passing by luck on CRLF, three docs:check rules that stayed green under sabotage. The standing answer: prove a new rule with a deliberate violation before trusting it, then grep the tree for the shape the rule cannot see.

  3. 03

    Gate the diff, read the report you have

    Mutation over changed files, e2e over reachable scenarios, one round of survivor-killing, and never re-running a gate to re-read its output.

  4. 04

    The author is the wrong reader

    The review is always an agent that did not write the diff. The pictures are read by an agent that does not know what they are for. The copy is read as sentences with real values in them. The plan is criticised before code exists.

  5. 05

    A lesson left in the chat is gone

    The retrospective is a gate that falls before the release. Each lesson has to land as a rule, a check or a skill line, and each landed rule displaces an older one under a line budget.

  6. 06

    Counts in prose rot

    A number that a list can move is removed rather than corrected, unless something depends on it, in which case a check holds it.
